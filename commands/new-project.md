# Command workflow: New project workflow

**Use when:** Trigger when the user requests a new app/service and product behavior is not yet specified.

1. Discover requirements incrementally and capture explicit assumptions/open questions.
2. Assess whether phases add value. For a potentially large project, ask whether the user wants phases; small projects can skip.
3. Produce specs and traceability; obtain explicit approval.
4. Recommend stack; compare any user-proposed stack fairly; obtain explicit confirmation.
5. Reuse suitable diagram; create/update only when none is suitable and user explicitly approves.
6. Create complexity-aware plan with unit and applicable integration tests; obtain explicit approval.
7. Implement in bounded TDD tasks, then Breaker, Reviewer, authorized fixes, final QA, optional release-readiness.
