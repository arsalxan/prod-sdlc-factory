# API design skill

Define resource/operation semantics, request/response schemas, types, validation, authentication/authorization, error format, pagination/filtering/sorting, idempotency, versioning/compatibility, rate limiting and observability as relevant. Make contracts testable and consistent with approved specs. Consider null/missing/empty distinctions, time zones, precision, duplicate requests, retries, and backwards compatibility. Document examples and failure cases. Avoid adding fields/behavior not in approved requirements without raising the change. Use contract/integration tests when interfaces cross component boundaries.
